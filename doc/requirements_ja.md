# 要求事項定義書

本ドキュメントは、関数型スタイルのタスクランナーおよびCI/CDツールである「Lask」の要求事項をまとめたものです。

## 1. 概要

Laskは「ローカルで検証可能」「型安全」「高いモジュール性」を目指した、開発者のための新しいタスクランナー・自動化ツールです。
Makefileの手軽さ、Task/Justのタスク管理能力、Earthly/Daggerのようなコンテナ統合による再現性を、関数型のシンプルなDSLと強力なエコシステム（LSPなど）によって提供します。

## 2. 解決したい課題（背景）

既存のCI/CDやタスクランナーには以下の課題が存在します。

1. **ローカルテストの困難さ (Push and Pray)**
   - 多くのCI/CDプラットフォームの設定（YAML等）はローカルで同一の環境を再現して実行することが難しく、リモートで失敗しては修正を繰り返す時間的ロスが大きい。
2. **スクリプトの無秩序化と再利用性の低さ**
   - 巨大なシェルスクリプトやMakefileはモジュール化が難しく、プロジェクト間での処理の使い回しがしにくい。引数やデフォルト値の管理も煩雑になりがち。
3. **静的検証の不足**
   - 実行前にエラー（引数不足、タイポ、型チェック）を発見する仕組みが弱く、実行時エラーになって初めて気付くことが多い。
4. **実行環境（ホスト依存）の暗黙化**
   - ホストマシンの依存パッケージによって結果が変わる問題（"It works on my machine"）。
5. **実行履歴の保管**
   - 実行結果のログやアーティファクトを、CI/CDの実行履歴として保存・参照する仕組みが弱い。

## 3. コア要件（提供価値）

これらの課題を解決するため、Laskは以下のコア要件を満たします。

### 3.1 関数型ベースの宣言的・コンポーザブルな構文
- タスクやジョブを「関数」として定義し、他の関数から呼び出したり、結果を組み合わせられること。
- 位置引数、キーワード引数、可変長引数、デフォルト引数など、モダンなプログラミング言語と同等の引数体系をサポートすること。

### 3.2 実行環境の透過的コンテナ統合
- ホスト環境での実行だけでなく、シームレスにコンテナ内でのタスク実行を言語レベルで指定可能にすること。これにより設定ファイルの増大を防ぎつつ環境の再現性を担保する。

### 3.3 堅牢な実行前静的解析
- ランタイム実行前に、引数不足や型不整合などの問題を検出する構文・型の静的解析機能を提供すること。

### 3.4 高度なエディタ支援 (DX)
- LSP（Language Server Protocol）などを通じ、エディタ上で補完、ホバー、エラーハイライトなどの強力な開発支援を受けられる体系にすること。

### 3.5 高いモジュール性と再利用性
- ファイル分割や別モジュールの機能インポートを促進し、巨大になりがちなCI/CDスクリプトを、チーム間・プロジェクト間で再利用可能な単位に分割できるようにすること。

## 4. 機能要件

### 4.1 言語・構文
1. **式ベースの統一的定義**: タスクやジョブを含むすべての要素を等価な式として宣言できること。
2. **基本データスキーマ**: 真偽値、数値、文字列、配列、オブジェクト等の基本データ型を備えること。
3. **環境参照型**: 実行環境（コンテナイメージなど）を表現する型を持ち、言語内オブジェクトとして扱えること。
4. **制御構造**: 条件分岐（if/else）やコレクションに対する反復・フィルタ操作など、タスク実行に必要なフロー制御構文を提供すること。
5. **関数制御**: ファーストクラス関数やクロージャをサポートし、再利用性を保てること。
6. **モジュール機能**: 他のファイルやパッケージの関数・変数を読み込み、グローバル空間を汚染せずに利用できるインポート機構を提供すること。
7. **シェル統合操作構文**: コマンドの呼び出しやシェル実行を簡潔に記述できる構文サポートを持つこと。
8. **式展開機構**: 文字列やコマンド表記の内部において、容易に変数や式を文字列展開できること。

### 4.2 インターフェース機能 (CLI/API)
1. **タスク実行**: スクリプト内の指定した関数（タスク）を実行できる。
2. **対話型環境 (REPL)**: コマンドや関数をその場で評価・確認できる対話型プロンプト（REPL環境）を提供する。
3. **式評価・出力**: 指定した関数を評価し、実行結果を他ツールが解釈し易い形式（JSON等）で出力できる。
4. **静的検証**: スクリプト内のコードの構文・参照エラーを静的検証できる。
5. **型推論**: 変数や関数の型推論結果を提供する。
6. **エディタ連携**: エディタ連携用のサーバー機能を提供する。

### 4.3 実行評価機能
1. **名前解決・スコープ**: 引数などのローカル束縛、自モジュール、インポート済みモジュール、組み込み関数の優先順序に基づき一貫したスコープ解決を行うこと（組み込みは最下位とし、ユーザー定義によるシャドーイングを許容する）。
2. **タスクの並列実行**: 依存関係のないタスク呼び出しやシェルコマンド群を並行して評価し、効率的に実行する並列機序を提供すること。
3. **I/Oマネジメント**: コマンド実行（ローカル/コンテナ等）に対してI/Oを扱い、ストリーム（標準出力/エラー）を適切にルーティングすること。
4. **外部入力の取り込み**: 実行時コマンドライン引数や標準入力を、スクリプト内で透過的に参照・利用する仕組みを提供すること。

## 5. 非機能要件

1. **パフォーマンス**
   - 解析および推論は十分に高速であり、エディタ連携時にも思考を妨げない応答性（数十ミリ秒以内の応答）を持たせること。
2. **ポータビリティ**
   - 実行基盤に依存せず、クロスプラットフォーム（macOS, Linux 環境等）で配布・実行可能であること。
3. **拡張性**
   - 組み込みのライブラリや関数群を追加・置換し、言語機能を容易に拡張できるように実行器モデルを汎用的に設計すること。

## 6. 要求仕様

ここでは満たすべき仕様を記載します。

* **言語パラダイム**
  * 関数型をベースとしつつ、Makefileやシェルスクリプトに慣れたユーザが自然に書ける手続的な記述スタイルもサポートする。
  * ラムダ式および高階関数をサポートする。

* **関数呼び出しと引数**
  * 関数はコマンドラインから呼び出すことができる。
  * 関数の引数は、一般的なCLIツールの規約に沿って自然に指定できること。
  * CLIで指定した引数は、関数定義側のキーワードパラメータに束縛できること。
  * 引数の解釈・デコード方法を指定できること。

* **データ型とシリアル化**
  * データ型の入出力は、シリアル化可能かつヒューマンリーダブルな形式で扱えること。
  * 関数値（ラムダ・クロージャを含む）、Void、および実行環境値（Environment）は直接のシリアル化対象とはせず、実行記録上で参照可能なメタデータ表現として扱うこと。
   * サポート対象の型を、基本型と合成型に分けて定義すること。
   * 基本型:
      * Any: 任意の値を許容する汎用型。
      * Number: 整数および浮動小数点数を扱う数値型。
      * String: UTF-8文字列を扱う文字列型。
      * Bool: true/false を扱う真偽値型。
      * Null: 値の不在を示す型。
      * Void: 戻り値が存在しないことを示す型。
   * 合成型:
      * Array<T>: 要素型を持つ配列型。要素型が Any の場合は混在要素を許容する。
      * Map<T>: 文字列キーを持つマップ型（キーは常に String）。
      * Record<...>: 固定フィールドを持つレコード型。
      * Function<Args..., R>: 引数型と戻り値型を持つ関数型（ラムダ式・高階関数を含む）。
   * 特殊型:
      * Environment: 実行環境（ローカル/コンテナ/リモート）を表す組み込み型。値は環境式によってのみ構成され、シリアル化はメタデータ表現に限られる、基本型とは異なる特殊な位置付けを持つ。
   * 注記: エラー値の型 Error は新たな基本型ではなく、基本型から構成される組み込みのレコード型エイリアス（Record<code: Number, message: String>）として提供する。

* **標準入出力とパイプ**
  * 標準入出力を通じて、関数間でデータを受け渡しできること。
  * 標準入力はEOFまで受け取った後に関数評価へ渡す方式をサポートし、実行中受信はサポート対象外とする。
  * 標準入力はUTF-8文字列として受け取り、行分割やJSON解釈などの構造化は、言語内の標準関数（split、fromJson等）で明示的に行うこと。デコード方式を実行時オプションで切り替える仕組みは提供しない（呼び出しごとにプログラムの意味が変わることを防ぐため）。

* **実行モデルとエラー処理**
  * 実行は逐次実行を基本としつつ、並列実行を可能とすること。
   * 非同期呼び出しおよび待機の指定手段を提供すること。
  * 通常は実行時エラー発生時に即時終了すること。
  * エラーから復旧する仕組みを提供すること。
  * 失敗時はエラーコードとエラーメッセージを返すこと。

* **型システム方針**
  * 型注釈は任意であり、型推論により型を決定できること。
  * オーバーロードはサポートしない。
  * 抽象型はサポートしない。

* **実行環境**
  * コマンド呼び出し時に実行環境を指定できること。
  * 実行環境として、ローカル環境、Dockerコンテナ、リモートサーバー等を対象にできること。

* **観測性と実行記録**
  * スタックトレースを常時記録できること。
  * 実行ログを標準エラーへ出力できること。
  * 関数の実行結果を標準出力へ出力できること。
  * 出力のエンコード方法を指定できること（既定値を定めること）。
  * 関数の呼び出し・戻り値・失敗を時系列イベントとして記録できること。
  * 実行イベントは追跡可能な識別子、対象関数、引数・戻り値の要約、失敗時のエラー情報を持てること。
  * 引数・戻り値に関数値が含まれる場合は、値本体ではなく参照情報として記録すること。
